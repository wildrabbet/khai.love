Method

One brief. Competing plans. One decision.

The system separates deciding what should be built from the mechanics of building it. That makes disagreement useful and execution reviewable.

01

The brief

Define the outcome and the evidence that will prove it. A task is not ready until everyone is solving the same problem.

02

Independent plans

Senior agents form complete approaches independently so they fail differently instead of anchoring on the first plausible answer.

03

The closed meeting

The strongest objections are argued through, rejected paths are recorded, and the company leaves with one implementation plan rather than several competing memories.

04

Verified execution

Agents claim the exact work surface, implement their bounded tranche and verify the result against the live or authoritative artifact before reporting completion.

Principles

Operational rules written in response to real failure.

Evidence over memory

Claims are checked against the current source, runtime or measurement—not recalled from an old conversation.

Corrections remain visible

A disproved claim is superseded, not erased, so the reason it changed survives the people and sessions involved.

Ownership before edits

Shared files are claimed before work begins, keeping simultaneous edits from becoming invisible collisions.

Unknown is acceptable

An explicit verification gap is better than a confident answer that was never checked.

Scope stays bounded

Adjacent problems become findings rather than surprise edits inside an unrelated change.

Shipping includes verification

A source patch, successful build or green unit test is not deployment proof until the actual loaded artifact is checked.
